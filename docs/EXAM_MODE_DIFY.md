# 本試験モード(問44〜46) Dify側の設定手順

アプリ側(このリポジトリ)の「📝 本試験の記述を採点(問44〜46)」は、Difyに次の形の文面を送ります。

```
本試験 問44 採点：<ユーザーの答案>
本試験 問45 採点：<ユーザーの答案>
本試験 問46 採点：<ユーザーの答案>
```

- 「本試験」「問44」「採点」の間は半角スペース1つ、コロンは **全角「：」** です。
- アプリは返事の中の **「◯/20」(最後に出てくるもの)** を読んで、問番号ごとの点数として保存します。  
  → 新しいノードの出力は、必ず既存の採点ノードと同じ形(最後に `採点結果 ◯/20`)にしてください。

これを受けるために、Difyのワークフローに **3つのLLMノード** を足します。所要時間はコピー作業込みで15〜20分です。

> 期限: 11/8(日)の19:00までに3ノードが「公開」されている状態にしてください。模範解答は試験当日の夜に貼ります(貼るまでは仮の文言のままでOK。貼ってから「公開」を押し直します)。

---

## 全体像

```
[開始] → [問題を選択(CASE分岐)] ┬ 既存のケース…(出題スタート など) → 既存ノード
                                ├ 新ケース: 本試験 問44 採点： → [LLM: 本試験 問44 採点] → 回答
                                ├ 新ケース: 本試験 問45 採点： → [LLM: 本試験 問45 採点] → 回答
                                └ 新ケース: 本試験 問46 採点： → [LLM: 本試験 問46 採点] → 回答
```

---

## 手順1: 既存の採点ノードを3つコピーする

1. DifyでコスモスKのアプリを開き、「オーケストレート」(ワークフロー編集画面)を開く。
2. 既存の採点用LLMノード(モデル `gpt-4.1`、名前は「LLM-answer」など、答案を採点しているノード)を右クリック → **「コピー」** → 空いている所で **「貼り付け」**。これを3回やって3つ作る。
3. それぞれのノード名を上の鉛筆マークから変える:
   - `本試験 問44 採点`
   - `本試験 問45 採点`
   - `本試験 問46 採点`
4. モデルは既存と同じ(`gpt-4.1`)のまま。温度などの設定もそのまま。

## 手順2: CASE分岐(問題を選択)に3つの条件を足す

1. 「問題を選択」と書かれた **条件分岐(IF/ELSE・CASE)** ノードをクリック。
2. 右側のパネルで **「+ ELIF」**(または「ケースを追加」)を押し、条件を足す。
   - 変数: ユーザーのメッセージ(`sys.query`。既存のケースで使っている変数と同じものを選ぶ)
   - 条件: **「で始まる」(start with)**
   - 値: `本試験 問44 採点：`  ← 全角コロンまでコピペ
3. 同じように `本試験 問45 採点：`、`本試験 問46 採点：` の2つも足す。
4. **順番に注意**: この3つのケースは、一覧の **いちばん上(既存のケースより前)** に置いてください。  
   既存のケースに「それ以外は答案として採点」のような広い条件があると、そちらが先に当たって本試験用ノードに届きません。ケースの左にあるつまみをドラッグで上に動かせます。
5. 各ケースの右端の「●」から線を引いて、手順1で作った対応するノードにつなぐ(問44のケース→「本試験 問44 採点」ノード)。
6. 3つのノードの出力を、既存の採点ノードと同じ **「回答」ノード**(または新しく「回答」ノードを足して)につなぐ。回答ノードの中身は `{{ 本試験 問44 採点.text }}` のように、そのLLMノードの `text` を選ぶ。

## 手順3: 答案の取り出し方(メッセージの先頭を外す)

ユーザーのメッセージには先頭に `本試験 問44 採点：` が付いています。  
いちばん簡単なのは **LLMに「先頭の文字列を無視して」と書く** 方法で、下のSYSTEMプロンプトにその指示を入れてあります(コードノードは不要)。

もしきっちり外したい場合は、分岐の後ろに **「コード」ノード**(Python)を1つ挟み、その出力をLLMに渡します:

```python
def main(query: str) -> dict:
    import re
    answer = re.sub(r'^本試験\s+問4[456]\s+採点：', '', query.strip()).strip()
    return {"answer": answer}
```

- 入力変数: `query` ← `sys.query`
- 出力変数: `answer`(string)
- LLMのUSERメッセージを `{{ コード.answer }}` にする

## 手順4: 3つのノードのプロンプトを書き換える

各ノードの **SYSTEM** を下の文に差し替えます(問番号の部分だけ44/45/46に変える)。  
**USER** は既存のまま(`{{ sys.query }}`)で構いません。

`【模範解答・採点基準をここに貼る】` の所に、試験当日の夜、予備校の模範解答と、自分で決めた採点基準(要素ごとの配点)を貼ります。

```
あなたは行政書士試験(記述式)の採点官です。これは2026年度 本試験の問44(配点20点)の、受験者の答案の予想採点です。

## 入力の扱い
ユーザーのメッセージは「本試験 問44 採点：」という接頭辞で始まります。接頭辞は無視し、その後ろの文章だけを受験者の答案として採点してください。答案が空・1〜2文字・明らかに無関係な場合は、全項目❌として0点にしてください。問題文は絶対に出力に書かないこと。

## 模範解答と採点基準
【模範解答・採点基準をここに貼る】
(例)
模範解答: ○○○○は△△△△であり、□□□□に対して××××を請求できる。
採点基準:
1. 「○○○○」を挙げている … 配点6点
2. 「△△△△」の要件に触れている … 配点6点
3. 「□□□□に対して××××を請求できる」と結論を書いている … 配点8点

## 採点ルール
- 採点基準ごとに判定する。完全に書けていれば ✅、意味は合っているが表現が不十分・語句が一部欠けていれば 🔺(部分点: 配点の半分。奇数なら0.5点刻み)、書けていなければ ❌。
- 同じ意味なら言い回しの違いは減点しない。法律用語は正確さを見る(例: 「取消し」と「無効」は別物)。
- 40字を大きく超えていても減点はしないが、答案の意味が通らない場合は該当項目を❌にする。
- 合計は小数(例: 9.5)でもよい。20点を超えないこと。

## 出力形式(必ずこの順番・この形で。既存の採点と同じ形式)
📋 採点基準ごとの判定
✅ 1. (基準の内容) → 配点6点／得点6点
🔺 2. (基準の内容)(部分点) → 配点6点／得点3点
❌ 3. (基準の内容) → 配点8点／得点0点

🧮 合計式: 6 + 3 + 0 = 9
採点結果 9/20

ポイント:

- `✅` `🔺` `❌` と `配点◯点／得点◯点`、`🧮`、`採点結果 ◯/20` の形は **既存の採点ノードと同じ** にしてください。アプリ側はこの形を読んで、20点メーターと✓・△・✕のカードに変換し、本試験の点数表に記録します。
- 「採点結果 ◯/20」の行は **最後に1回だけ** 書かせてください。アプリは「◯/20」の **最後の出現** を読みます。
- 問45・問46は「問44」の所を置き換えるだけ。

## 手順5: 公開して、テストする

1. 右上の **「公開する」→「公開」**。(模範解答を貼る前でも一度公開しておくと、分岐と出力形式の確認ができます)
2. アプリ(ブラウザ版)のURLに `?exam=1` を付けて開く(例: `https://<アプリのURL>/?exam=1`)。試験前でも「📝 本試験の記述を採点(問44〜46)」が出ます。
3. 問44を選び、次の答案を入れて「AI採点する」:

```
AはBに対し、詐欺による取消しを主張し、所有権移転登記の抹消を請求できる。
```

   あるいはDifyの「プレビュー」から直接、次の文を送ってもOKです:

```
本試験 問44 採点：AはBに対し、詐欺による取消しを主張し、所有権移転登記の抹消を請求できる。
```

4. 確認すること:
   - 返事が「📋…🧮…採点結果 ◯/20」の形で返ってくる(問題文が出ていないこと)
   - アプリ側で、答案の下に **「📝 本試験 記述式の予想」カード** が出て、問44の欄に点数が入る
   - ホーム画面の「あと◯回」が **減っていない**(本試験モードは無料枠を消費しません)
   - 「Xに投稿」を押すとXの投稿画面が開き、文面に点数とストアURLが入っている
5. 問45・問46も同じようにテストする。

## 手順6: 試験当日の夜(11/8)

1. 各予備校の模範解答が出そろったら、3つのノードの `【模範解答・採点基準をここに貼る】` を実物に差し替える。
2. 採点基準の配点の合計が **20点** になっているか確認する。
3. **「公開する」→「公開」** を押し直す(押さないと反映されません)。

## よくあるつまずき

| 症状 | 原因と直し方 |
| --- | --- |
| 本試験の答案を送っても、普段の採点(練習問題)の返事になる | 分岐の順番。3つの新ケースを既存ケースより **上** に移す。コロンが半角「:」になっていないか確認 |
| アプリの点数表に「—」のまま入らない | 返事に「◯/20」が無い。SYSTEMの出力形式の `採点結果 9/20` の行が削られていないか確認 |
| 返事に問題文が出てしまう | SYSTEMの「問題文は絶対に出力に書かないこと」が消えていないか確認 |
| 「あと◯回」が減る | アプリ側の判定は `本試験 問4x 採点：` で始まるかどうか。文面を変えた場合は元に戻す |


## 追記(11/8): 採点基準は自動で入る形に変更

採点基準はDifyに貼らず、GitHubのブランチ `exam-rubric` の `exam-rubric.json` に置きます。アプリが送信のたびにその問の基準を取りに行き、答案の後ろに `【採点基準(速報)】` として付けてDifyへ送ります(画面には出ません)。基準の作成・更新はClaudeの予約タスクが行います。

Dify側は **LLM 3 のSYSTEMを下の文に一度だけ差し替えて「公開」** すれば、以後さわる必要はありません。

```
あなたは行政書士試験(記述式)の採点官です。これは2026年度 本試験の記述式(問44・問45・問46、各20点)の、受験者の答案の予想採点です。

## 入力の扱い
ユーザーのメッセージは「本試験 問4◯ 採点：」で始まり、その後ろに受験者の答案、さらにその後ろに「【採点基準(速報)】」から始まる模範解答と採点基準が付いています。
- 「本試験 問4◯ 採点：」から「【採点基準(速報)】」の手前までが受験者の答案です。
- 「【採点基準(速報)】」以降に書かれた模範解答と採点基準だけを使って採点してください。自分の知識で基準を作り替えないこと。
- メッセージに「【採点基準(速報)】」が無い場合は、採点せずに「この問題の模範解答は準備中です。予備校各社の解答例がそろいしだい、採点できるようになります。」とだけ返してください。
- 答案が空・1〜2文字・明らかに無関係な場合は、全項目❌として0点にしてください。
- 問題文・模範解答・採点基準の文章そのものは出力に書き写さないこと(基準の要点を短く書くのはよい)。

## 採点ルール
- 採点基準ごとに判定する。完全に書けていれば ✅、意味は合っているが表現が不十分・語句が一部欠けていれば 🔺(部分点: 配点の半分。奇数なら0.5点刻み)、書けていなければ ❌。
- 採点基準に「別解」「言い換え可」とあるものは、それも正解として扱う。同じ意味なら言い回しの違いは減点しない。法律用語は正確さを見る(例: 「取消し」と「無効」は別物)。
- 判定の前に、答案の文字を基準の語句と一つずつ照らし合わせること。答案に書いてある語句を❌にしないこと。
- 40字を大きく超えていても減点はしないが、答案の意味が通らない場合は該当項目を❌にする。
- 合計は小数(例: 9.5)でもよい。20点を超えないこと。
